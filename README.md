# 森林防火巡护管理系统

面向森林火险监测、巡护任务调度、防火设施维护与应急响应指挥的林区防火管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 演练筹备批次的数据流

`drillplan` 是唯一跨表编排的模块，规则全部集中在 `frontend/src/api/drill-plan.ts`：

- 按演练主题**多选参演队伍、所需装备、管制道路**，整组排定筹备/实施/总结日期，实时展示
  `目标人数 - 去重后参演人数 = 人数缺口`。不同林场队伍**允许混合，但只有管理员可混合编组**，
  林场值班员只能操作归属本林场的数据，只读查看员所有写入口均被拒绝。
- 旧演练缺装备明细时，按**同主题、最近一次、已进入历史（已实施/已总结/已归档）**的演练兼容继承，
  且只继承当前身份林场范围内、未被占用的装备。
- **提交筹备是一个事务**：先完成三环节前置校验（队伍值班调整、装备领用清单、道路管制提醒），
  任一环节失败不落任何单据；全部通过后单次原子写入，落库失败也按快照整体回退
  （见 `local-store.ts` 的 `commitAll`）。
- 联动生成：值勤排班（值班调整）、`equipissue`（装备领用清单）、`equipoccupy`（演练占用台账）、
  `roadnotice`（道路临时管制提醒）以及一条正式演练记录。
- **装备占用台账是单一事实源**：消防装备页（其他模块）执行「领用装备」也会同步写入占用台账，
  演练筹备因此选不到已被他处领用的装备；占用中装备禁止送检/报废，演练值班中的队伍禁止再下达出动。
- **去重与幂等**：重复勾选队伍/装备只计一次；同一提交凭证的草稿/提交重复操作只生效一次；
  总结提交统一归还装备、解除道路与占用，重复释放幂等。
- **历史演练记录保持原主题**：被批次联动生成的演练记录只能随批次（确认实施/提交总结）推进，
  通用动作入口对其只读保护。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `forest-fire-patrol:entries` 这一项，或调用 `resetModule(模块)`。
